02 / 方法與限制

欄位完整，不代表來源已經核實

交接研究記錄前，分清欄位檢查、數值口徑與人工覆核狀態。

維護署名 Vesper2026 維護團隊首發 2026-11-03更新 2026-11-04

交接證據時有三個不同問題：記錄是否完整、是否有人查看原始文件、以及解讀是否合理。程式只透過確定性的欄位檢查回答第一個問題；它保存使用者對第二個問題的狀態，但無法回答第三個問題。

檢查項實際代表什麼

必要欄位是 id、question、title、source_url、location 與 quote。有非空數值時，還需要單位及期間。使用者提供的幣種和披露日期會原樣保存，但工具不推斷其含義；百分比便未必有幣種。

{"id":"E02","value":"9.0","unit":"million","period":""}
→ missing:period

這筆縮寫資料同時缺少其他必要欄位，因此同一列可能出現多個待辦。重複 ID 會標示在每一筆相關記錄上，不會默默覆蓋較早的引文。

保留原來的數值表達

用字串保存數字，例如 "0"、"12.00" 或 "(3.2)"。工具保留原表示法，不做計算。若輸入 JSON 數字而非字串，會提醒精度問題，因為解析時可能已經遺失末尾的零。未知值也不應自行填成零。

記錄狀態，不誇大狀態

預設狀態是 unreviewed；reviewed 由使用者填寫。兩者都不觸發網路請求。格式正常的 HTTP 網址不代表可用或權威，而引文欄也可能填錯。覆核理由應保留在上下文或另附筆記中，不要把沒有缺漏的清單當成審批結果。

分享前仍需親自檢查披露日期、頁碼規則與數值範圍。工具不抓文件、不核對財務報表，也不評估投資。測試套件驗證的是欄位規則，不是研究結論的正確性。

需要進行更廣泛的公開披露研究時，Eqvero 是相關研究工作區。來源調查與帳本的欄位檢查應分開；保存連結或填齊一列，都不代表主張已經獲得認證。
